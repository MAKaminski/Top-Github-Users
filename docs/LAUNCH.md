# Product Hunt launch kit

Everything needed to fill in the submission form, plus the checks worth doing first.

Regenerate the gallery any time with a server running:

```bash
pnpm build && pnpm start          # one shell
node tests/launch-media.mjs       # another; writes ./launch-media
```

It photographs the live site, so the numbers in the shots are whatever the site is
actually serving. Re-run it after a crawl and the media updates itself.

---

## Before submitting

- [ ] `NEXT_PUBLIC_POSTHOG_KEY` set in Vercel (Production **and** Preview) — without it
      analytics silently does nothing, which is the correct default but not what you want
      on launch day.
- [ ] `NEXT_PUBLIC_SITE_URL` set, if a real domain is pointed at the deployment. One
      variable moves every canonical, sitemap entry, OG image URL and JSON-LD `@id`.
- [ ] Check the developer count on the live site and update the copy below if the corpus
      has grown. **Do not quote a number the site is not serving.**
- [ ] `curl -s $SITE/robots.txt` and `curl -s $SITE/sitemap/0.xml | head` return what you
      expect.
- [ ] Paste the URL into a Slack or X compose box and confirm the Open Graph card renders.
- [ ] `claude mcp add --transport http commitgraph $SITE/api/mcp` — someone in the thread
      will ask, and having tried it that morning is worth more than believing it works.

## First comment

Posted automatically at launch. This is the highest-leverage text in the whole submission —
it is what decides whether the thread has a conversation in it.

```
Hey Product Hunt 👋

Commitgraph started with a small annoyance. I wanted to know who the most
active developers on GitHub actually are — and every site that answers
that question hands you the same thing: a paginated HTML table of usernames
and one number.

That number is the least interesting thing in the data. It can't show you
the shape of someone's year, whether a rank is climbing or collapsing, how
contributions relate to followers, or where the activity really is.

So I built the version I wanted. Every ranking has a chart behind it:
371-day contribution heatmaps, rank-movement bump charts, a tile-grid world
map, follower/contribution scatter. Worldwide, by country, and by city.
There's a free REST API and an MCP server over the same snapshot, so you
can ask an AI assistant "who's the top developer in Seoul" and it can
actually go and check.

The part I didn't expect to matter most: saying what I *don't* know.
Location is free text people type themselves. GitHub only exposes private
contributions as a total. Some calendars are estimated rather than fetched.
Accounts that are obviously automation get excluded. All of it is labelled
in the UI and explained on /methodology, because every other site in this
category presents its ranking as fact.

Two things that surprised me while building:

GH Archive turns out to be a gift — 27 million events processed for zero
API budget, which is how the candidate list gets built without hammering
GitHub.

And I was wrong about the thing I was most confident in. I'd designed the
whole pipeline around batching 100 users per GraphQL query. GitHub serves
exactly 10 before it returns "Resource limits for this query exceeded."
Measuring it instead of assuming it changed the entire collection schedule.

It's free, there's no signup, and the data is a committed snapshot you can
diff in git.

Would genuinely love to know: what's the first thing you looked up? And
what's missing that you expected to be there?
```

Both stories in that comment are true and checkable — the GH Archive figure is in the
crawler logs, and the alias ceiling is reproducible with `pnpm crawl --tier=verify`. Keep
them that way. A Product Hunt audience contains people who will check.

## Answers worth having ready

**"How is this different from committers.top / gitstar-ranking?"**
They answer the same question with a table. This one visualises the data behind the number,
covers cities as well as countries, and publishes a methodology page saying where it is
wrong. It also has an API — REST and MCP — which none of them do.

**"Where does the data come from?"**
GH Archive's public event stream for discovery, GitHub's GraphQL API for the profile
figures. Snapshots are committed to git, so any ranking can be diffed against the day
before.

**"Is my private work counted?"**
Only as a total, because that is all GitHub exposes. Never the underlying work, and never
anything that identifies a private repository.

**"Can I get myself added / fix my location?"**
Location comes from the free-text field on your GitHub profile. Fix it there and the next
snapshot picks it up. This is the single largest source of error on the site and
`/methodology` says so.

**"Why is someone with 300k contributions missing?"**
Above 300,000 in twelve months — over 820 every day without a break — accounts are excluded
as automation. They are listed openly in `data/flagged.json` and on `/methodology` rather
than being quietly dropped.
